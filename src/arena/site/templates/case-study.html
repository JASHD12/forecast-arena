The problem

Claims that an AI agent forecasts better than a plain statistical model are easy to make and hard to check: the agent can be shown the answer by accident, a good week gets quoted and a bad one forgotten, and the cost of the model calls goes unmentioned. This project asks the question as a benchmark that cannot be gamed afterwards.

The design

  • Every forecast is locked before the answer exists. Questions about tomorrow come from public data; forecasts go into an append-only, hash-chained ledger on a git branch, and a command re-checks that none was written after its question locked.
  • No look-ahead. Every forecaster reads data through an as-of gateway, so it sees only what had been published at forecast time.
  • A fair contest. Baselines, a gradient-boosted model with champion/challenger promotion, and several LLM agents answer the same questions; scores are Brier scores with day-block bootstrap intervals, and a difference is called supported only when its interval excludes zero.
  • Cost and honesty built in. Hard daily token caps, a recorded skip instead of a guess when a forecaster fails, pre-registered experiments and published negative results.

What I would do next

  • Fit the weather error model on 60 days of stored forecast errors instead of fixed spreads, and add the archived grid-forecast vintages to the electricity model.
  • Run the pre-registered test of an agent that starts from the ML forecast and only adjusts for news.
  • Re-test the news-tone idea on fresh days once enough archived aggregates exist, before believing any gain.
