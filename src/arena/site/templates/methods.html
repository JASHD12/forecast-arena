Methods

This page is a summary; the full methods page grows with the project.

Rules

  • Forecast before truth. Every question has a lock time (09:30 UTC on the batch day). Forecasts are written and committed to the public ledger before it. A late run writes nothing; nothing is backdated.
  • Append-only ledger. Questions, forecasts, resolutions and run records are appended to files on the public ledger branch and sealed with a SHA-256 hash chain. Corrections are new records.
  • No leakage. Forecasters only see data that was available at forecast time, through one as-of gateway with conservative availability rules.
  • Honest scoring. Brier and log scores on probabilities clipped to [0.01, 0.99]; the base-rate forecaster is always shown; voided questions are excluded and counted.

Limits

Git commit times are evidence, not cryptographic proof. The public branch history, the hash chain and the GitHub Actions run logs together make silent edits detectable by anyone who has cloned the ledger branch.
