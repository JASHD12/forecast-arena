Forecasters and models

Status: baselines and the LLM forecasters run live; the numerical models use a separate model per topic; the table below identifies published versions and their domains. The table "Running right now" below shows exactly what is live.

LLM forecasters (Anthropic Claude)

Three live designs on the same questions: data-grounded (as-of data in the prompt), a tool-using agent (news-headline search via GDELT, Wikipedia summaries; at most 4 tool calls, 90 s). The tool-using design also runs as a LangGraph state machine. A fourth, question-only design ran until 2026-11-27 and was retired (cost; its earlier forecasts stay). Experimental variants are built and off until their pre-registered evaluations pass: a calculator and reference estimate, forecasting skills loaded on demand, hybrid retrieval with guards, and a committee of specialist agents. Beside the Claude forecasters run two open-weight designs on CPU: a stock Qwen2.5-1.5B model and an experimental QLoRA-tuned copy of it{% if llm_page_available %} (see the LLM engineering page for what the tuning did and did not achieve){% endif %}. Strict JSON output contract with one repair attempt, prompt-injection hygiene, versioned prompts, and a hard daily token and request budget enforced in code.

Multi-agent committee over A2A (experimental, off)

A chair calls four specialist agents (reference estimate, base rate and similar past questions, news scout, skeptic) as separate agents of the Agent2Agent (A2A) protocol, using the official SDK and an in-process transport (no network socket in the daily job). A failed member is recorded; below a pre-registered quorum the committee skips instead of guessing. Its pre-registered evaluation found no benefit over one agent with skills, so it stays off{% if llm_page_available %} (the evaluation is on the LLM engineering page){% endif %}.

Electricity: quantile gradient boosting

scikit-learn HistGradientBoostingRegressor with quantile loss predicts the full distribution of tomorrow's price statistics; probabilities are read off the predicted CDF and Platt-calibrated on out-of-fold predictions from expanding windows with a gap (no shuffling, no leakage).

Wikipedia attention: boosted classifier

HistGradientBoostingClassifier on 7-day attention trajectories (growth, volatility, rank, presence), with time-series cross-validation and Platt calibration.

Exchange rates and crypto: volatility models

EWMA variance (RiskMetrics, λ = 0.94) with fat-tailed Student-t returns for "big move" questions; direction is held at 50% unless a backtest proves skill.

Weather: numerical-weather-prediction rules

Transparent probabilistic rules on the DWD MOSMIX forecast (normal error models for temperature, gusts and city duels), fixed before any outcome was seen.

Baselines

Base rate and persistence, replayed through the real question and resolver code so they are fair from day one. Every leaderboard shows them.

Evaluation and statistics

  • Proper scoring rules: Brier and log score on clipped probabilities, skill against the base rate.
  • Calibration: reliability diagrams, expected calibration error, Murphy decomposition (reliability, resolution, uncertainty).
  • Uncertainty: day-block bootstrap confidence intervals and paired differences; a result is "supported" only if its interval excludes zero.
  • Diebold-Mariano test (Newey-West variance, Harvey-Leybourne-Newbold correction) as a second opinion on every backtest comparison.
  • Walk-forward backtests kept strictly separate from the live record.
  • No leakage by construction: every forecaster sees data only through an as-of gateway that knows when each value was published.

Agent interfaces: MCP and A2A

  • MCP (agent to tool): arena mcp serves a local copy of the ledger to any MCP host, read-only, with four tools.
  • A2A (agent to agent): arena-oracle answers questions about the published record (questions, forecasts, the leaderboard, how the methods work) as an A2A agent with an Agent Card, mounted next to the REST API in the Docker image and tested there and on a local Kubernetes cluster in CI. It is built on the same code as the MCP server, refuses advice, stock and personal-data questions, and cannot write. It is not hosted publicly: this site is static.
  • REST API: FastAPI over the same snapshot, with OpenAPI docs; also local and in CI only.

Data analytics

  • DuckDB SQL over the whole ledger at every build; the queries and their results are published on Open data & SQL.
  • Open data in Parquet (zstd-compressed, columnar): questions, forecasts, resolutions and skips, readable by any Parquet reader; the analysis notebook reads it with DuckDB, pandas and Polars.

MLOps

  • Model registry with versioned artefacts and model cards; promotions are new records, never overwrites.
  • Weekly champion/challenger retraining with a written promotion rule, tracked in MLflow: for electricity, scikit-learn gradient boosting competes with a LightGBM challenger whose hyperparameters are tuned by Optuna on time-series folds; SHAP explains the LightGBM model when it wins.
  • Data-drift monitoring with Evidently.
  • Probabilistic forecast evaluation: pinball (quantile) loss and empirical coverage of the 80% and 90% prediction intervals for the electricity model's 13-quantile distributions, with quantile rearrangement against crossing.
  • Explainability: permutation feature importance (scikit-learn) for the promoted electricity model, published with every weekly run on Experiments.
  • Versioning everywhere: every forecast records its model, prompt and settings, and version changes are visible on the site.

Data engineering and integrity

  • Six live public data sources (SMARD, DWD via Bright Sky, Wikimedia + Wikidata, ECB, GDELT, CoinGecko), with recorded fixtures for offline tests.
  • Append-only ledger on a git branch, sealed with a SHA-256 hash chain; anyone can verify it with one command.
  • Idempotent, restartable jobs with atomic writes; time injected through a clock; Europe/Berlin day handling (23/25-hour days).

Infrastructure and quality

  • GitHub Actions schedules (evening, morning, resolve every three hours, weekly), GitHub Pages hosting, Docker image.
  • CI: ruff lint, mypy static type checking, hundreds of unit tests, an offline end-to-end run, accessibility checks (axe-core), dependency audit; code reaches production only after a green run (a separate stable branch).
  • Static, private-by-design site: small self-hosted JavaScript enhancements, no cookies or third-party requests.
