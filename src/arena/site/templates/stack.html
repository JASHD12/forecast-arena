How it is built

Tech stack

A production-style forecasting system: live data pipelines, classical ML and LLMs side by side, proper scoring and uncertainty, MLOps, and a tamper-evident public record. Everything below is in the open-source repository.

Forecasters and models

Status: baselines and the LLM forecasters run live; the classical ML models are trained and backtested (and retrained weekly) and join the live record together with the remaining topics. The table "Running right now" below shows exactly what is live.

LLM forecasters (Anthropic Claude)

Three designs on the same questions: zero-shot (question only), data-grounded (as-of data in the prompt), and a tool-using agent (news-headline search via GDELT, Wikipedia summaries; at most 4 tool calls, 90 s). Strict JSON output contract with one repair attempt, prompt-injection hygiene, versioned prompts, and a hard daily token and request budget enforced in code.

Electricity: quantile gradient boosting

scikit-learn HistGradientBoostingRegressor with quantile loss predicts the full distribution of tomorrow's price statistics; probabilities are read off the predicted CDF and Platt-calibrated on out-of-fold predictions from expanding windows with a gap (no shuffling, no leakage).

Wikipedia attention: boosted classifier

HistGradientBoostingClassifier on 7-day attention trajectories (growth, volatility, rank, presence), with time-series cross-validation and Platt calibration.

Exchange rates and crypto: volatility models

EWMA variance (RiskMetrics, λ = 0.94) with fat-tailed Student-t returns for "big move" questions; direction is held at 50% unless a backtest proves skill.

Weather: numerical-weather-prediction rules

Transparent probabilistic rules on the DWD MOSMIX forecast (normal error models for temperature, gusts and city duels), fixed before any outcome was seen.

Baselines

Base rate and persistence, replayed through the real question and resolver code so they are fair from day one. Every leaderboard shows them.

Evaluation and statistics

  • Proper scoring rules: Brier and log score on clipped probabilities, skill against the base rate.
  • Calibration: reliability diagrams, expected calibration error, Murphy decomposition (reliability, resolution, uncertainty).
  • Uncertainty: day-block bootstrap confidence intervals and paired differences; a result is "supported" only if its interval excludes zero.
  • Walk-forward backtests kept strictly separate from the live record.
  • No leakage by construction: every forecaster sees data only through an as-of gateway that knows when each value was published.

MLOps

  • Model registry with versioned artefacts and model cards; promotions are new records, never overwrites.
  • Weekly champion/challenger retraining with a written promotion rule, tracked in MLflow.
  • Data-drift monitoring with Evidently.
  • Versioning everywhere: every forecast records its model, prompt and settings, and version changes are visible on the site.

Data engineering and integrity

  • Five live public data sources (SMARD, DWD via Bright Sky, Wikimedia + Wikidata, ECB, GDELT), with recorded fixtures for offline tests.
  • Append-only ledger on a git branch, sealed with a SHA-256 hash chain; anyone can verify it with one command.
  • Idempotent, restartable jobs with atomic writes; time injected through a clock; Europe/Berlin day handling (23/25-hour days).

Infrastructure and quality

  • GitHub Actions schedules (morning, resolve four times a day, weekly), GitHub Pages hosting, Docker image.
  • CI: ruff lint, hundreds of unit tests, an offline end-to-end run, accessibility checks (axe-core), dependency audit; code reaches production only after a green run (a separate stable branch).
  • Static, private-by-design site: no JavaScript, cookies or third-party requests.
